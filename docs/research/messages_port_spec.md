# Porting NCLives' SMS pipeline to JackieLives — implementation spec

_Written 2026-08-25. Research only: nothing in this repo was changed to produce it._

**Supersedes `docs/research/texting_research.md` (2026-07-03).** That spike's "Path A — runtime
injection from CET Lua" is **dead**, definitively: `JournalManager`
(`scripts/core/systems/journalManager.script:388-425`) exposes only readers plus
`ChangeEntryState(uniquePath, className, state, notifyOption)` and `ChangeEntryStateByHash`. Every
`JournalPhoneMessage` is an `importonly` read-only class loaded from a cooked `.journal`. There is no
create-a-message API from Lua **or** from redscript, and no reference mod has one. Its "Path B" is
what NCLives shipped — minus the questphase graph, which we do not need because scheduling lives in
Lua. Read `../NCLives/docs/MESSAGES.md` in full before writing any code; this document assumes it.

The port is **content plus plumbing, not research.** Every hard question was answered in NCLives
between v1.45 and v1.91, and the two engine bugs that made the feature unusable in the wild are
already fixed in the code being copied.

7. **NEW — numeric avatar support.** `build()` at **:245** does `tdbid_str(c["avatar"])`, which only

### 1d. `mod/JackieLives/messages.lua` — the exact edits

The module is a **global** (`Msg = require("messages")`), because `init.lua` is at Lua's 200-local
cap. Same reason as `Fam` / `VO` / `Native` (`init.lua:74-77`).

| NCLives site | change |

**No redscript is involved anywhere in this feature**, so the `JLVO_`/`NCLVO_` prefix-collision rule
(CLAUDE.md) does not apply to it. Lua globals live in per-mod CET states and cannot collide either —
`Msg` is safe as a name. The three things that *are* shared and *do* need the `jackielives_`
prefix: **game facts**, **localization keys**, and **journal `uniquePath`s**.

### 1e. ⚠️ THE ONSCREENS FILENAME TRAP — read before writing a line of code

`archive/source/mod/jackielives/onscreens/en-us/jackielives_onscreens.json.json` **already exists and
is owned by `tools/gen_vomap.py`** (`gen_vomap.py:73,264-298`). It carries exactly one entry —
`jl_vomap_token`, the archive-presence beacon that `jlArchiveLoaded()` (`init.lua:3549-3572`) reads,
and whose value is the voice map's version fingerprint. Pointing the ported `gen_messages.py` at that
filename would silently overwrite the beacon, `jlArchiveLoaded()` would return false forever, and
`VO.femaleTakeId` would refuse to substitute **all 47** female-take ids. Silent, total, and it looks
like a voice bug, not a messages bug.

**Fix: give the message text its own file, `jackielives_msgs.json`, and list BOTH under `en-us` in the
`.xl`.** ArchiveXL accepts a list of paths per locale (ArchiveXL `src/App/Extensions/Localization/Config.cpp`
"resource path or list of paths"); NCLives does exactly this today
(`../NCLives/archive/pc/mod/NCLives.archive.xl`, the `en-us:` block).

## 2. Naming: the journal tree, and Jackie's vanilla contact

### He is already a contact — verified locally, this session

Extracted `base\journal\cooked_journal.journal` from the Mac install (`basegame_4_gamedata.archive`,
4,785,509 bytes) with `../small_cyberpunk_mods/TimedChoices/redlib.py` and parsed it: 47,478 exports,
**145 `gameJournalContact`s**. Two are Jackie:

| contact `id` | name | avatarID (TweakDBID, uint64) | conversations |
|---|---|---|---|
| `jackie` | `LocKey#10799` | **121253599929** | `q001_waiting_after_victor`, `q003_all_foods_come_back`, `q004_status_update`, `q003_all_foods_before`, `q001_left_jackie_car` |
| `jackie_dead` | `LocKey#10799` | 122982124291 | none |

### ArchiveXL deep-merges into an existing contact — verified, not assumed

`reference_mods/Panam Romance Messages Mod-.../archive/pc/mod/PRME_4.0.archive` contains
`mod\mrbill61\prme\journal\prme_journal.journal`, which declares contacts **`panam`, `mitch`, `saul`**
— vanilla ids, with the vanilla `avatarID`s and `LocKey` names — carrying **only its own new
conversations** (`hat`, `br`, `bm`, `er`, `date`, …). None of those ids appear in the vanilla contact's
conversation list, and PRME does not re-declare the vanilla ones. Vanilla Panam messages still work in
that mod. **Conclusion: ArchiveXL merges the journal by id chain and appends unknown children, so a new
conversation can be hung under `contacts/jackie` without touching anything CDPR owns.**

### The scheme

```
contacts/jackie                          gameJournalContact          (vanilla, merged into)
contacts/jackie/jackielives              gameJournalPhoneConversation (ours, new)
contacts/jackie/jackielives/<beat>_b<N>          gameJournalPhoneMessage
contacts/jackie/jackielives/<beat>_g             gameJournalPhoneChoiceGroup
contacts/jackie/jackielives/<beat>_g/<replyId>   gameJournalPhoneChoiceEntry
contacts/jackie/jackielives/<beat>_<replyId>_f<N> gameJournalPhoneMessage  (his answer)
```

Content-file `contact` block:

```json
"contact": {
  "id": "jackie",
  "conversation": "jackielives",
  "name": "Jackie",
  "avatar": 121253599929,
  "type": "Texter",
  "flatLayout": false
}
```

- **`conversation: "jackielives"`** is the one id that must never collide with a CDPR conversation id
  under `contacts/jackie`. The five vanilla ones are listed above; `jackielives` is not among them.
- **`avatar: 121253599929`** is Jackie's own photo, reused as a raw TweakDBID (needs the generator
  change in §1c.7). Its symbolic name could not be recovered — the TweakDBID encodes
  `len=28 | fnv1a32=0x3b471ab9` and no obvious `PhoneAvatars.*` string of length 28 hashes to it — so
  pass the number, which is exactly what the engine stores. Fallback if it ever misbehaves:
  `"PhoneAvatars.Avatar_Unknown"` (what NCLives uses).
- **`flatLayout: false`** on purpose. Vanilla `jackie` has `useFlatMessageLayout` unset (= 0) and five
  real conversations; forcing flat layout would restyle his prologue threads. Flat layout is right for
  a contact who is *only* ours, which is the fallback below.
- **`name`** is emitted as our own LocKey with the text `"Jackie"`. If the merge preserves the
  existing contact's scalar fields it is ignored; if it overwrites them, the display name is still
  correct. (Vanilla stores the string `LocKey#10799` in the `value` slot, per the redlib read — that
  shape is available as an escape hatch, but our own key is the safer default.)

### Risk, and the one-line fallback

Merging into `contacts/jackie` is the *nicer* result (his real face, his real name, one thread) and is
proven by PRME, but it does put our conversation next to entries the prologue quests own, and
`ensureContact()` (`messages.lua:171-176`) sets `contacts/jackie` itself to `Active`. If that ever
misbehaves in game, switching to a private contact is **one line of content**:

```json
"contact": { "id": "jackielives_jackie", "conversation": "thread", "flatLayout": true, ... }
```

Everything downstream — journal, index, Lua — is generated from that field. Ship the vanilla-`jackie`
version, keep this paragraph.

## 3. LocKey namespace and the hashing rule

```
KEY_PREFIX = "jackielives_msg_"          # gen_messages.py:43
```

Every emitted key: `jackielives_msg_jackie_<beat>_b<N>`, `jackielives_msg_jackie_<beat>_g_<replyId>`,
`jackielives_msg_jackie_name`, `jackielives_msg_blank`.

Rule, unchanged from NCLives (`gen_messages.py:50-59`, `docs/MESSAGES.md` §2):

```python
def fnv1a64(s):
    h = 0xCBF29CE484222325
    for b in s.encode("utf-8"):
        h = ((h ^ b) * 0x100000001B3) & 0xFFFFFFFFFFFFFFFF
    return str(h)
```

- `text` is a `localizationString`: `{"unk1": fnv1a64(key), "value": key}`.
- The onscreens entry carries `primaryKey = fnv1a64(key)` **and** `secondaryKey = key`.
- A wrong `unk1` renders a literal `LocKey#<id>` in the phone. There is no other symptom.
- ⚠️ **Never key onscreens by bare display text.** BowieKnife99 shipped a crash caused by FNV-1a
  hashes of short English phrases colliding with base-game localization entries.
- The empty-title trick (`gen_messages.py:259`): the conversation `title` hashes
  `jackielives_msg_blank`, whose text is `""`, so `hasValidTitle == false` and the contact row previews
  the last message like a real thread. `unk1: "0"` does **not** work.
- `jl_vomap_token` (the beacon, `gen_vomap.py:80`) is outside this namespace and must stay that way.

## 5. The Lua runtime API after porting

Loaded as a global in `init.lua` beside `Fam`/`VO`/`Native`:

```lua
Msg = require("messages")   -- GLOBAL (200-local cap)
```

Public surface (signatures as they look **after** the single-persona simplification):

```lua
Msg.bind{ ... }                 -- once, in onInit; see the table below
Msg.onInit()                    -- drops ALL per-session scratch. MUST run on every CET reload:
                                -- the throttles hold clock values and the clock restarts at 0.
Msg.tick(dt)                    -- once per frame from the main tick; self-guards on Config.messages.enabled

Msg.unlocked()      -> bool     -- has the chain started for this save
Msg.unlock(why)                 -- start it (idempotent); first text lands firstMessageHours later
Msg.forceStart()    -> bool     -- the Native Settings "start texting now" button

Msg.pendingVenue()  -> venueKey|nil   -- engine asks each tick; place Jackie at that venue
Msg.rendezvousMet()             -- engine calls once he has actually been placed there

Msg.sendNow(beatId) -> bool     -- debug: send this beat, or the next scheduled one
Msg.status()        -> string   -- one line for the CET panel
Msg.diagnose()      -> {string} -- walks the chain in break-order and names the FIRST thing wrong
```

Bindings JackieLives passes (contrast with `../NCLives/mod/NCLives/init.lua:12292-12370`):

```lua
Msg.bind{
  log = log, Config = Config,
  gameSeconds = getGameSeconds,                        -- init.lua:1445
  clock       = function() return JL.clock or 0 end,
  factGet     = function(n) local v; pcall(function() v = Game.GetQuestsSystem():GetFactStr(n) end); return v end,
  factSet     = function(n, v) pcall(function() Game.GetQuestsSystem():SetFactStr(n, v) end) end,
  gate        = function() return Retrieval.isUnlocked() end,   -- NEW binding, replaces gatePassed()
  famTier     = function() return Fam.tier() end,               -- familiarity.lua:122
  famAdd      = function(_key, why, n) Fam.add(why, n) end,     -- familiarity.lua:101
  busy        = function() return (DialogUI and DialogUI.active) or false end,
  inCombat    = function() return jlInCombat() end,
  spawned     = function() return (JL.summon and JL.summon.spawn and JL.summon.spawn.handle) ~= nil end,
  venueKnown  = function(v) ... end,                            -- config.lua:3065 venue list
}
```

**The gate is the one genuine design decision.** NCLives hard-codes Lucy's jacket
(`messages.lua:250-257`). JackieLives' equivalent is `Retrieval.isUnlocked()`
(`retrieval.lua:737`, stage ≥ REUNITED) — Jackie texts once he is actually back, which is
retro-compatible for free (an old save passes on the next load) and needs no journal reads. Inject it
as `Msg.env.gate` rather than hard-coding, so `test_messages.lua` can drive it.

Engine hooks to add in `init.lua`, both trivial (NCLives: `init.lua:13241-13296`, `13642`):
1. `Perf`-free one-liner in the main tick: `pcall(function() Msg.tick(dt) end)`.
2. The rendezvous placer: each tick ask `Msg.pendingVenue()`; when V is within
   `Config.messages.rendezvousSpawnRadius` of that venue and Jackie is not already spawned, place him
   *at* the venue (seated if it has a sit workspot) and call `Msg.rendezvousMet()`. JackieLives already
   has the venue walk/snap/sit machinery.

## 6. Mac vs Windows, and the staleness trap

**Mac (everything except one command):**
- author `content/jackie_messages.json`
- `python3 tools/gen_messages.py` → journal JSON + onscreens JSON + `messages_index.lua`
- `python3 tools/audit_messages.py` → which beats still have no authored replies
- `lua tools/test_messages.lua`, plus the existing suite (`loadsim`, `test_vo`, `test_dialogui`, …)
- `python3 tools/build_archive.py --digest` → what the sources hash to right now

**Windows (one command, and it is not in `deploy.bat`):**
```
python tools\build_archive.py        (or double-click build_archive.bat)
```
It regenerates, runs WolvenKit `convert deserialize` on every `.json.json`, `pack`s a clean tree, copies
`JackieLives.archive` into the repo, writes `JackieLives.archive.stamp`, and deploys to the game.
⚠️ `WolvenKit.CLI.exe` is a **separate download** (`WolvenKit.Console-<version>.zip`), not the GUI
installer. ⚠️ The game locks installed archives while running.

### `build_archive.py` edits (JackieLives line numbers)

1. **:42-44** add `JOURNAL_SRC = os.path.join(ARCH_SRC, "journal", "jackielives_messages.journal.json")`.
2. **:90-92** `all_sources()` must include the journal **and** the new
   `jackielives_msgs.json.json` per locale — otherwise `source_digest()` (**:95-108**) does not cover
   the message text and the `.stamp` gate goes blind to exactly the thing it is guarding.
3. **:144-155** convert loop: unchanged once `all_sources()` is right.
4. **:159-169** staging loop: add a `journal` case (the journal is not per-locale, so it does not fit
   the `(kind, root, stem)` tuple shape — add it separately, copying to
   `stage/mod/jackielives/journal/`) and the `msgs` stem alongside `onscreens`.
5. **Consider adding** `subprocess.run([sys.executable, gen_messages.py])` as step 0, the way NCLives
   does (`../NCLives/tools/build_archive.py:156-158`), so an archive can never be built from stale
   content. NCLives' file also runs `gen_vomap.py`'s output through — do **not** copy that: JackieLives'
   vomap is Mac-generated and committed on purpose (`build_archive.py:20-22`).

### The staleness trap, stated plainly

`package_nexus.sh:132-160` refuses to build a release zip when `--digest` ≠ the committed `.stamp`.
Once the journal and the message onscreens are inside the digest, **editing `content/*.json` on the
Mac immediately makes the zip un-buildable until Windows rebuilds.** That is the feature, not a bug —
but NCLives burned a whole session on it, three wrong diagnoses deep, so:

- The digest is over **generated CR2W-JSON sources**, not over `content/`. A commit that only touched
  the scheduler is not a content change. Read `source_digest()` before naming what drifted.
- The gate is **all-or-nothing over the whole source set**. A vomap change makes the messages look
  stale and vice versa.
- Fixing a stale stamp is always the same one-sitting order: regenerate on the Mac → `build_archive`
  on Windows → commit `archive/pc/mod/` (all three files: `.archive`, `.archive.xl`, `.archive.stamp`).
  Never ship the Lua ahead of the archive.
- ⚠️ A message added to the JSON alone **will not appear in game**, with no error and no log line.

## 7. The content-authoring contract

**You write exactly one file: `content/jackie_messages.json`.** Nothing else. It is the single source
of truth — the generator writes the journal, the localization and the Lua index from it, and
`check_parity()` (`gen_messages.py:426-450`) fails the build if they could ever disagree.

```jsonc
{
  "contact": { "id": "jackie", "conversation": "jackielives",
               "name": "Jackie", "avatar": 121253599929, "type": "Texter", "flatLayout": false },

  "beats": [
    {
      "id": "open01",                  // unique, stable, NEVER reused or renumbered (paths + facts)
      "kind": "opener",                // see the table below
      "tier": 0,                       // familiarity tier this becomes eligible at (0..3), and above
      "once": true,                    // optional: fires at most once per save
      "afterHours": 30,                // optional: not before N in-game hours after the chain started
      "venue": "noodle",               // REQUIRED on kind:"invite" — one of the 7 venue keys
      "bubbles": [                     // his grey blobs, in order. 1-3 short ones, not a paragraph.
        "Heard you were askin' after me.",
        "Don't go soft on me now, hermano."
      ],
      "replies": [                     // optional. V's options. 2-3 is right.
        { "id": "yes",  "text": "Wouldn't dream of it.", "fam": 1 },
        { "id": "meet", "text": "I'll be there.",        "fam": 1, "accept": true },
        { "id": "none", "text": "[Don't answer]",        "fam": -1 }
      ],
      "followups": {                   // what HE says back — keyed by reply id, at BEAT level
        "yes":  ["Course you wouldn't.", "That's my boy."],
        "meet": ["Bien. Don't be late."],
        "none": ["...Yeah. Figured."]
      }
    }
  ]
}
```

**Field rules that are load-bearing:**

| field | rule |
|---|---|
| `id` | unique across the file, stable forever. It becomes a journal path and a fact bit. |
| `kind` | one of `opener`, `checkin`, `question`, `invite`, `standup`, `afterdate`, `outgoing` |
| `tier` | `0` professional → `3` close. Eligible at its tier **and above**, so tier-0 beats keep recycling. |
| `bubbles` | omit **only** for `kind: "outgoing"` — a beat with neither bubbles nor replies is a hard error (`gen_messages.py:224-225`). |
| `replies[].fam` | familiarity awarded for tapping it. Negative is allowed. |
| `replies[].accept` | `true` only on an `invite`'s "I'll be there" — that is what arms the rendezvous. |
| `followups` | a **beat-level map keyed by reply id**, not a field on the reply. Getting this wrong reports fully-authored beats as unanswered (`audit_messages.py:29-35`). |
| `venue` | `noodle · misty · coyote · afterlife · ginger · redwood · lizzies` |
| text | **cannot be interpolated at runtime** — it is baked into the archive. Author one invite *per venue*, never a `{venue}` placeholder. |

**Kinds, and what the scheduler does with each** (`messages.lua:346-363`):
`opener` jumps the queue and is normally `once: true`. `checkin` and `question` are the everyday pool,
drawn with a shuffle bag so you see all of a tier before any repeat. `invite` needs tier ≥ 2 and no
rendezvous already booked. `standup` fires once when V never showed. `afterdate` becomes eligible right
after a met rendezvous. `outgoing` is **V starting the conversation** — no `bubbles`, only `replies`;
the runtime leaves the group armed on the thread and keeps V's side open for
`outgoingChainTurns` (3) turns before a cooldown.

**Volume, from what shipped:** Lucy = 43 beats (19 checkin, 12 outgoing, 3 invite, 3 afterdate,
2 opener, 2 question, 2 standup); Valerie = 31. Aim for **~30-40 beats**. Antonia's standing rule from
the v1.91 player report: *every incoming beat should have authored replies and at least a short
conversation after it — roughly 50:50 between longer exchanges and short factual ones.*
`tools/audit_messages.py` is the worklist and the check that it stays done.

**After writing:** `python3 tools/gen_messages.py` → `python3 tools/audit_messages.py` →
`lua tools/test_messages.lua` → **`python tools\build_archive.py` on Windows** → commit
`archive/pc/mod/` (all three files) together with the content and the generated index.

## 8. Traps NCLives already hit — do not re-derive any of these

1. **Two active choice groups on one thread = an unusable messenger.** (v1.91, reported 2026-08-22:
   *"I can only reply to the first message and after that it bugs out."*) `armReplies` never put the
   previous group back to `Inactive`, so every group she had ever sent stayed Active and piled up;
   tapping one did nothing because `pollReply` only watches the latest beat. Invariant: **exactly one
   choice group Active at a time, ever** — `rt().armed` is it, and arming anything disarms the previous
   one (`messages.lua:396-457`). `disarmGroup` must also clear the outgoing latch `rt().out`, or V's
   side of the thread is dead for the rest of the save. Copy that code and its comments verbatim; the
   ported `test_messages.lua` holds the invariant across ten exchanges.

2. **Never gate an SMS timer on real seconds alone.** A pending question blocked the whole schedule on
   a 30-minute *real* clock in a game with a Skip Time button: sleep through a day and a half in four
   real seconds and no text can ever arrive. Fixed with two clocks — `until_` (real) and `gameUntil`
   (in-game hours), whichever expires first (`messages.lua:441-448`).

3. **The cadence ramp is by COUNT, not by tier.** Familiarity only moves when V *talks* to him, so a
   player who has only ever texted stays at tier 0 forever. NCLives' first five texts use
   `earlyGapHours = {10, 22}` and everything after `lateGapHours = {24, 40}`
   (`../NCLives/mod/NCLives/config.lua:1555-1612`). Copy the shape; do not resurrect `gapHoursByTier`.

4. **Being on `bind()`'s allow-list is not being bound.** The whole feature was dead in NCLives v1.72
   because two bindings were listed and never passed — and 83 offline checks passed anyway, because
   the test harness stubs them itself. Same blind spot as the CET RTTI-globals bug. When you add a
   binding, add it in **both** places, and make `Msg.diagnose()` name it.

5. **The onscreens filename collision.** §1e. It would silently kill the female voice takes.

6. **`Msg.onInit()` must drop every throttle,** including `pollAt`/`gateAt`. They hold clock values and
   CET's clock restarts at 0 on a soft reload; a stale "next poll at 2000" means the unlock gate never
   polls again for the session (`messages.lua:696-708`).

7. **Enum arguments as plain strings** — `"Active"` / `"Notify"`, never `gameJournalEntryState.Active`.
   Both work from CET, but the bare-global RTTI trap (CLAUDE.md, `dialogui.lua`) does not apply to
   strings.

8. **`Inactive` (silent) before `Active` (notify)** is the delivery idiom, and it is what makes a beat
   re-fireable so a small pool carries a long playthrough (BowieKnife99 `bowieknife99.reds:456-457`).

9. **Fail soft with no archive.** Every path check goes through `entry()`; a player who installs only
   the CET folder must get exactly the mod they had before, with no errors. `Msg.diagnose()` exists so
   "she never texts" is never unfalsifiable — it checks the **journal**, which is the one fact that
   separates "archive not loaded" from every software problem on our side.
